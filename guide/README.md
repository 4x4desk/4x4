# The 4x4 guide

A short way in to 4x4, for anyone new to it: a person who wants to build an app, or an AI agent about to help with a change. Read it before the code. Each page is one screen and one idea, and they are meant to be read in this order.

1. [What 4x4 is](what-is-4x4.md): a desktop for large monitors, who it's for, and which levels exist today.
2. [The layers](layers.md): the five layers the desk is built in, and which ones change often.
3. [Apps](apps.md): an app is one folder; how it is made, updated and shared.
4. [Zones and workspaces](workspaces.md): where apps sit on the screen, and how a set of them gets a name.
5. [The look](design.md): the few design rules every builder needs.
6. [How we work](how-we-work.md): how this project thinks and writes. If you are an AI agent, read this one before you change anything.
7. [Words](words.md): the words 4x4 uses, one line each.

After the guide, the next places to read are [`contracts/`](../contracts/), the promises the pieces keep to each other, and [`apps/parts/`](../apps/parts/), the shared parts every app is built from. [`CONTRIBUTING.md`](../CONTRIBUTING.md) says how to send a change.

Something here unclear, or no longer true? Open an [issue](https://github.com/4x4desk/4x4/issues) or ask in [Discussions](https://github.com/4x4desk/4x4/discussions).
